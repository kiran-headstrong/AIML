Internal Training Content Search Assistant

A low-cost, local-first Streamlit prototype that lets operations users search across mixed internal training content — PDFs, TXT/Markdown notes, and screenshots — and retrieve the most relevant guidance with clear source references, a query category, a confidence indicator, and a suggested next step.

Python 3.10+ Streamlit sentence-transformers Chroma / FAISS Local-first · No GPU · No paid cloud

Overview

The operations enablement team answers repeated process questions by manually checking shared folders, PDF training decks, screenshots from internal tools, and short SOP notes. The same topics are explained in multiple places but cannot be searched together, which slows response time. This prototype ingests a bounded corpus, builds a searchable index using local embeddings, and presents source-backed answers through a simple Streamlit search interface.

It is deliberately scoped as a retrieval prototype — not a broad chatbot, a full multimodal reasoning system, or an enterprise knowledge platform.

Corpus size: ~30–60 text documents/sections and ~20–40 screenshots.
Cost: runs on a standard CPU laptop with no GPU and no paid cloud service.

Introduction & Scope

Deliverables (20-day cycle)

  • Complete source code and the Streamlit prototype
  • Ingestion and indexing scripts
  • A structured metadata file plus an optional screenshot metadata file
  • 20–30 test queries with recorded retrieved outputs
  • A README, notes on assumptions and limitations, and a short evaluation summary
The corpus combines a sanitized starter dataset pack with additional publicly available reference content used to extend retrieval testing.

Functional Requirements

Thirteen requirements written in EARS-style acceptance criteria drive the implementation. Each is summarized below with its acceptance criteria.

Req 1 Local Corpus Ingestion

As an operations user, I want the Assistant to ingest a local folder of mixed training content, so that scattered PDFs, notes, and screenshots become searchable together.

  1. Read PDF, TXT, Markdown, and image files (PNG, JPG, JPEG) from the folder and subfolders.
  2. Load an optional CSV/JSON metadata file and associate entries with source files.
  3. Skip unsupported extensions and record the skipped name in an ingestion log.
  4. Skip unreadable/unparseable files, log a descriptive error, and continue.
  5. Report counts of ingested documents, ingested screenshots, and skipped files.

Req 2 PDF Text Extraction & Chunking

  1. Extract text with the page number for each segment.
  2. Divide extracted text into chunks not exceeding the configured maximum size.
  3. Associate each chunk with its source file name and page reference.
  4. A PDF with no extractable text is logged and produces zero chunks.

Req 3 Text Note Ingestion & Chunking

  1. Extract TXT/Markdown text and divide it into size-bounded chunks.
  2. Associate each note chunk with its source file and a section reference where available.

Req 4 Screenshot Indexing

  1. Record file name and file path as a Screenshot_Item.
  2. When OCR is enabled and available, extract and store text from the image.
  3. When manual metadata is provided, associate its topic tag and description.
  4. When OCR is disabled/unavailable, index by file name and any manual metadata.

Req 5 Metadata Tagging & Storage

  1. Record topic tag, doc type, source file, and section/page reference per item.
  2. Persist all metadata to a local file (SQLite, CSV, or JSON).
  3. Load persisted metadata on startup without requiring re-ingestion.

Req 6 Local Embedding & Vector Indexing

  1. Produce embeddings using a local sentence-transformers model.
  2. Generate embeddings without a GPU and without a paid cloud service.
  3. Store each embedding with a reference to its chunk in a local FAISS/Chroma store.
  4. Load a persisted index on startup without regenerating embeddings.

Req 7 Query Retrieval

  1. Embed a non-empty query with the same model and search the index.
  2. Return top matches ranked by similarity, limited to a configured maximum.
  3. Return screenshot matches ranked by relevance using metadata and extracted text.
  4. Reject empty queries with a prompt and perform no retrieval.
  5. Return an empty result set with a no-match indicator below the similarity threshold.

Req 8 Query Categorization

  1. Assign exactly one category from the fixed set of five.
  2. Display the assigned category with the results.

Req 9 Source-Backed Answer Draft

  1. Produce a draft of no more than 6 lines derived only from retrieved items.
  2. Include references to the supporting source items.
  3. On no matches, state that no supporting content was found and omit guidance.

Req 10 Result Presentation

  1. For text matches: show title, page/section, source file, and a short excerpt.
  2. For screenshot matches: show preview/filename, topic tag, and metadata/OCR text.
  3. Display a Confidence_Indicator of High, Medium, or Low.
  4. Display a suggested next step: use the source, review the file, or escalate.

Req 11 Low-Confidence Handling

  1. Below the Medium threshold, set confidence to Low and suggest escalation.
  2. While Low, limit the draft to retrieved content and indicate low confidence.

Req 12 Local Operation Without Paid Cloud

  1. Ingest, index, and retrieve using local components without a GPU.
  2. Perform core search and retrieval without a paid cloud service.
  3. Fall back to grounded extraction when an optional model is unavailable.

Req 13 Evaluation With Sample Queries

  1. Execute at least 20 predefined sample queries against the corpus.
  2. Record text references, screenshot matches, category, and confidence per query.
  3. Write recorded outputs to a local evaluation output file.

Design Overview

Built with Python and Streamlit, the system ingests a bounded corpus, builds a persistent local index using sentence-transformers embeddings and a Chroma/FAISS vector store, and presents source-backed answers. Every drafted answer is grounded strictly in retrieved corpus content, with a qualitative confidence indicator and a suggested next step. Answer drafting is optional and pluggable: when a local model (Ollama) or external API is unavailable, the system falls back to a deterministic grounded-extractive draft.

Design Goals

Local-first, zero paid dependency — all core functionality runs on a CPU laptop (Req 6, 12).
Persistence and reuse — restarts do not require re-ingestion or re-embedding (Req 5.3, 6.4).
Resilient ingestion — a single bad file never aborts the pipeline (Req 1.3, 1.4, 2.4).
Honest confidence — low-confidence results are surfaced explicitly (Req 9.3, 11).
Reproducible evaluation — a scripted harness runs ≥20 queries and writes structured outputs (Req 13).

Architecture

The system has three runtime phases: Build (offline), Load (startup), and Query (interactive). Build is executed by ingestion/indexing scripts; Load and Query happen inside the Streamlit app.

Phase Flow

PhaseRuns InResponsibility
Buildscripts/build.pyWalk corpus → extract (PDF/notes/screenshots) → chunk → embed → upsert to Vector_Index + persist Metadata_Store + write ingestion log.
LoadApp startupLoad persisted vector index and metadata store into memory (cached with @st.cache_resource).
QueryStreamlit appCategorize query → embed → search → threshold → rank → draft grounded answer → present sources, confidence, next step.
Evalscripts/evaluate.pyRun ≥20 sample queries through the retriever and write structured outputs.

Layering

The design enforces separation between I/O, indexing, and presentation so the retrieval logic can be tested in isolation:

  • Extraction layer (ingestion/) — file reading, PDF/text extraction, chunking, screenshot indexing. Pure transformations from file bytes to chunk/item objects.
  • Index layer (index/) — embeddings + vector store + metadata store, wrapping external libraries behind narrow interfaces.
  • Retrieval layer (retrieval/) — query embedding, similarity search, thresholding, categorization, answer drafting. The primary target of property-based tests, using an in-memory fake index.
  • Presentation layer (app.py) — Streamlit UI, result rendering, confidence and next-step display.

Components & Interfaces

Interfaces are expressed as Python type signatures (Protocols / dataclasses).

Ingestion_Component

ingest_folder never raises on a single-file failure; it records a SkippedEntry(name, reason) and continues (Req 1.4).

class IngestionComponent: def ingest_folder(self, folder_path: str) -> IngestionResult: ... @dataclass class IngestionResult: text_chunks: list[TextChunk] screenshot_items: list[ScreenshotItem] ingested_doc_count: int # Req 1.5 ingested_screenshot_count: int skipped: list[SkippedEntry] # unsupported ext + parse failures

PDF_Extractor & Chunker

If a PDF yields no extractable text, the extractor returns an empty list; the orchestrator logs "no extractable text" and produces zero chunks (Req 2.4). Chunking is size-bounded, splitting on paragraph/sentence boundaries and hard-splitting only when a single unit exceeds the limit.

class PdfExtractor: def extract(self, path: str) -> list[PageText]: ... # Req 2.1 @dataclass class PageText: page_number: int # 1-based text: str class Chunker: def __init__(self, max_chunk_size: int, overlap: int = 0): ... def chunk(self, text: str) -> list[str]: ... # Req 2.2, 3.1

Screenshot_Indexer & Metadata_Loader

Embedding_Component & Vector_Index

Cosine similarity is normalized to [0, 1] so thresholds (Req 7.5, 11.1) are stable across backends.

class Embedder: def embed(self, texts: list[str]) -> list[list[float]]: ... # Req 6.1, 6.2 def embed_query(self, query: str) -> list[float]: ... # Req 7.1 class VectorIndex(Protocol): def upsert(self, entries: list[IndexEntry]) -> None: ... # Req 6.3 def search(self, query_vec: list[float], top_k: int) -> list[Match]: ... # Req 7.2 def persist(self) -> None: ... # Req 6.3 @classmethod def load(cls, path: str) -> "VectorIndex": ... # Req 6.4

Answer_Drafter (strategy)

OllamaDrafter / OpenAIDrafter catch connection/availability errors and the caller falls back to ExtractiveDrafter (Req 12.3). All drafters produce text derived only from the outcome; on no-match they return a "no supporting content found" statement with no guidance (Req 9.3).

class AnswerDrafter(Protocol): def draft(self, outcome: RetrievalOutcome) -> AnswerDraft: ... class ExtractiveDrafter: # default, no external deps (Req 12.3 fallback) class OllamaDrafter: # optional local LLM class OpenAIDrafter: # optional external API @dataclass class AnswerDraft: text: str # <= 6 lines, grounded only in retrieved items (Req 9.1) sources: list[SourceRef] # Req 9.2 low_confidence_note: bool # Req 11.2

Correctness Properties

Fourteen properties formalize what the system must do across all valid executions. Each is validated by a property-based test using hypothesis.

#PropertyValidates
1Ingestion partitions input files — supported text → doc count, screenshots → screenshot count, unsupported → skipped; counts + skipped equal total files walked.Req 1.1, 1.3, 1.5
2Ingestion is resilient to per-file failures — an arbitrary failing subset never raises; each failing file is skipped with a reason; good files still produce items.Req 1.4
3Chunk size is bounded — every chunk length ≤ N, and concatenation of chunks (ignoring overlap) covers the non-whitespace content.Req 2.2, 3.1
4Every chunk carries provenance — non-empty source_file, plus page_reference (PDF) or section_reference (note heading).Req 2.3, 3.2
5Screenshot indexing preserves identity and applies metadata — records file_name/file_path; applies topic/description; ocr_text None when disabled.Req 1.2, 4.1, 4.3, 4.4
6Metadata store round-trip — persist then reload yields items equal across all recorded fields.Req 5.1, 5.2, 5.3
7Retrieval ranking, limit, and reference consistency — matches ordered by descending score, at most top_k, every id resolves to a stored item.Req 6.3, 7.1, 7.2, 7.3
8Below-threshold retrieval yields a no-match result — empty match sets and no_match=true when nothing reaches min_similarity.Req 7.5
9Query categorization is total and single-valued — returns exactly one member of the fixed category set for any query.Req 8.1
10Empty queries are rejected without retrieval — whitespace-only/empty queries return the prompt and never call the retriever.Req 7.4
11Confidence and next-step mapping — exactly one confidence label, monotonic in s per thresholds; Low ⇒ escalate next step.Req 10.3, 10.4, 11.1
12Answer drafts are grounded — ≤ 6 lines; matches ⇒ non-empty sources from actual items; no-match ⇒ no sources/guidance; Low ⇒ low_confidence_note true.Req 9.1, 9.2, 9.3, 11.2
13Answer drafting falls back to grounded extraction — when the primary drafter is unavailable/raises, a valid extractive draft is returned instead of an error.Req 12.3
14Evaluation output is complete — exactly one output record per query, each with text references, screenshot matches, category, and confidence.Req 13.2
Environment constraints (Req 6.2, 12.1, 12.2), external-library / file-I/O behavior (Req 2.1, 4.2, 6.1, 6.4, 13.3), and UI rendering (Req 8.2, 10.1, 10.2) are covered by smoke, example, and integration tests rather than by properties.

Testing Strategy

The strategy combines property-based tests for input-varying logic with example, integration, and smoke tests for external dependencies and UI. Retrieval, chunking, categorization, confidence, and drafting logic are tested in isolation using an in-memory fake VectorIndex and a deterministic fake Embedder, so tests run fast on CPU without loading the real model.

Property-Based

  • Library: hypothesis (not hand-rolled).
  • Min 100 examples: @settings(max_examples=100, deadline=None).
  • One test per Correctness Property (1–14).
  • Tagged # Feature: internal-training-content-search, Property N.

Example-Based

  • PDF page-number association on fixture PDFs (Req 2.1) + empty-PDF path (Req 2.4).
  • Embedding shape/determinism: 384-dim vector, stable output (Req 6.1).
  • Render-helper completeness for text and screenshot payloads (Req 10.1, 10.2).
  • Category label appears in the rendered payload (Req 8.2).

Integration

  • Build → persist → reload → query, asserting identical top-k results (Req 6.4).
  • Optional OCR path against a fixture image, auto-skipped without Tesseract (Req 4.2).
  • Evaluation harness end-to-end writing an output file (Req 13.3).

Smoke

  • CPU-only build and query with no GPU (Req 6.2, 12.1).
  • Default ANSWER_MODEL=extractive, no network (Req 12.2).
  • Sample-query set contains at least 20 queries (Req 13.1).
Execution notes: Run once (not watch mode) via pytest -q. Real-model and OCR tests are marked @pytest.mark.slow / @pytest.mark.ocr and skip gracefully when resources are unavailable.

Post-Build Enhancements

After the core build satisfied all 13 functional requirements and 14 correctness properties, the following enhancements were added to improve usability, retrieval quality, and answer presentation. All 109 tests continue to pass with these changes.

UX Conversational Chat Interface

The single-query search box was upgraded to a full chat interface using st.chat_input and st.chat_message. Conversation history is preserved in st.session_state, so users can review previous questions and answers and ask follow-up questions in sequence. A sidebar "Clear history" button resets the conversation.

UX Streaming & Readable Formatting

  • Streaming answers — responses render word-by-word via st.write_stream for a natural typing effect.
  • Adaptive markdown formatting — raw extractive text is reformatted based on its structure: section labels (e.g. "Viewer:", "Processor:") become bold headers, bullet-like content becomes clean lists, and paragraph text is preserved as prose instead of forcing everything into bullets.
  • Column layout — confidence, next step, and category are shown side by side with dividers for clarity.

Retrieval Screenshot Embedding in the Vector Index

Originally screenshots were saved only to the metadata store and were not semantically searchable. The build pipeline now embeds each screenshot's topic_tag, description, and any OCR text into the vector index alongside text chunks, so screenshot-focused queries reliably return the relevant image. A populated metadata.json in the corpus supplies rich descriptions for each screenshot.

Retrieval Ranking & Categorization Quality

  • Meta-document exclusion — internal_search_use_cases.md (a list of example questions) was matching almost every query. It is now excluded via a configurable EXCLUDE_FILES setting so real training content ranks first.
  • Source deduplication — only the highest-scored chunk per source file is returned, giving more diverse results instead of the same file repeated.
  • Expanded categorizer keywords — domain-specific terms (access, approval, escalation, refund, filter, quality) were added, and matching now scores by hit count so the best-fitting category wins. Fixes prior mislabeling (e.g. access queries tagged as "Screenshot Lookup").

Reliability Tuned Confidence Thresholds

Empirical scoring showed on-topic queries score ~0.77–0.87 while off-topic queries (e.g. "payroll", "weather") score ~0.54–0.67. Thresholds were tuned to separate these cleanly:

SettingSpec DefaultTuned (.env)

Off-topic queries now correctly return a no-match instead of confidently returning irrelevant results. Spec defaults remain in config.py; the tuned values live in .env.

Reliability No-Match & Low-Confidence Fallback Guidance

When no content clears the threshold, the app shows actionable next steps: rephrase the query, review the list of available corpus topics, escalate to the operations lead, or request that content be added. Low-confidence results display a similar guidance block so users know to verify against the original sources.

Config Full .env Configuration

Every setting (model, chunking, retrieval, thresholds, answer model, and all data paths) is now overridable through a documented .env file loaded via python-dotenv, with the spec defaults as fallbacks.

Ops Environment & Documentation

  • Streamlit config — a .streamlit/config.toml disables the file watcher to stop it from scanning hundreds of unused transformers vision modules that made the app hang.
  • Dependency pin — transformers pinned to a stable 4.x line to avoid the vision-module bloat in 5.x.
  • README — added step-by-step run instructions, configuration table, project structure, and optional OCR / LLM setup.
  • Filled evaluation template — all 20 sample queries executed with recorded sources, relevance scores, grounding, screenshot presence, and confidence (average relevance 4.1/5, 100% grounded, 90% screenshot return).
Impact: The two originally-failing screenshot queries (Q003, Q009) now return the expected PNG, category labels are accurate, off-topic queries are correctly rejected, and answers are presented in a readable, conversational format — all while the full property-based and example test suite (109 tests) continues to pass.
